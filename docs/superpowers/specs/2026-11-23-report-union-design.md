# M2.4：显式报表来源与 UNION ALL 编译设计

日期：2026-11-23

状态：用户已同意显式报表来源方案；本文待用户复核，尚未开始功能实现。
基线：`fdb23f7`，M2.3 已提交；398 项测试、14 条黄金用例通过。

## 1. 目标与方案选择

为 `source_mode=report/union` 增加确定性报表编译分支：单月查对应报表，多月分别读取后 UNION ALL。
用户已选择语义层显式登记报表来源，不采用硬编码表名规则，也不建设自动报表家族发现机制。

继续遵守：Intent 不包含 SQL；L3 零模型调用、不连接数据库、不自由猜表；L4 独立重解析最终 SQL 文本。
不把已预计算的不良率再次 SUM/AVG，不把缺失月份或权限不足伪装成成功的部分结果。

## 2. 已核对的现有代码与用例

- `MetricDef.formula/source_tables` 描述当前明细计算；不能覆盖它们来切换到报表，否则会改变 plain 分支。
- 目前 `compile_intent` 返回 Select，且对根节点检查 FROM；新增 UNION 后须扩展为 Query，并分别检查每个 SELECT 分支。
- `sources.py` 的两表上限和 JOIN 基数规则只服务明细关联，不能套到三个月以上的报表拼接。
- `permissions.py` 和行策略构造器可以在每个单表分支复用；白名单、空 Scope 和空行策略的安全契约不能回退。
- L4 目前全局收集表别名，UNION 分支须使用互不冲突的别名，避免重复别名覆盖列目录。
- AQ-006 要求五级分类口径的产品不良率，`rpt_npl_by_overdue_202604` 的同名 npl_rate 不能混用。
- fixture 已有标准产品报表 202604、202605、202606；时间列 stat_month 使用 YYYYMM 字符串。
- fixture 标准报表的主键是 `(stat_month, prd_no)`，与本轮“每月、每产品一行”的读取形状一致。

## 3. 支持与明确排除

### 支持

- 同一个指标同时保留明细计算定义和可选报表来源定义，按 source_mode 分流。
- 单个指标、按已登记粒度读取一个或多个明确月份。
- `report` 与 `union` 均进入报表路径；月份数决定形状，而不是让 source_mode 强行指定 SQL 节点。
- 一个去重后的月份返回 SELECT；两个及以上月份返回 UNION ALL。
- 报表粒度维度的展示、eq/in 业务过滤、精确码值转换，以及逐分表的表/列/行权限。
- 合法跨年、闰年日期及已解析的完整月份区间，月份排序与去重保持确定性。

### 不支持

- 报表 JOIN、跨口径拼接、动态推导或扫描表名、未经登记的备用报表。
- 把报表结果再次汇总成更粗粒度，尤其不良率等非可加指标的求和、平均或跨月总值。
- 报表与 delta/yoy/mom/rate、全局 Top N、每月 Top N 混用。
- 日粒度报表、部分月份区间、季度/年度自然语言推算、多指标报表。
- 因缺表、缺配置或权限不足而跳过某个月，或自动回退到明细计算。

以上越界均明确报错；plain、JOIN、delta、每月 Top N 的既有能力和黄金 SQL 保持不变。

## 4. L0 报表元数据

新增独立的 `ReportDef`，由 `SemanticCatalog.reports` 按 metric_code 索引；
`SemanticCatalog.build` 接受可选报表定义序列，缺省为空，兼容旧调用。
类型放在单独的 `semantic/report.py`，不让现有明细模型承担报表路由。

一个定义包含：

| 字段 | 含义 | 产品不良率示例 |
|---|---|---|
| metric_code | 对应现有指标编码，决定业务口径 | npl_ratio |
| value_column | 预计算结果的物理列，不接受表达式 | npl_rate |
| month_column | 物理月份列，格式固定 YYYYMM | stat_month |
| dimensions | 业务维度 code → 本报表的编号/展示列 | product → prd_no / prd_nm |
| partitions | 月份 → 明确物理表名 | 202604 → rpt_npl_by_product_202604 |

维度列配置复用 `LevelDef` 的 group_by/display，但 table 必须留空：每个分支使用当前分表，不能暗含 JOIN。
报表不改写 plain 分支的 LevelDef，也不接受需要外部维表的维度。

配置须校验：指标存在；同指标不重复登记；月份格式有效；表名和列名非空；列名为单一标识符；
维度 code 存在；物理输出别名不冲突；不能把不同粒度的列或任意 SQL 片段塞入字段。
一个 profile 的所有分表承诺同列布局、单位、业务口径和唯一粒度。

配置是可信知识输入，但不等于证明真实数据满足它。
本轮不自动判定两张同名 npl_rate 报表的业务含义，正确映射由维护者登记，靠结果与来源测试守住。

## 5. 时间输入与缺月行为

不增加自然语言时间解析，仅消费已有 TimeRange。

1. grain=month 的 points：具体日期表示所属整月，将其规范化到 YYYYMM。
2. grain=month_end 的 points：日期必须确为月末，规范化到 YYYYMM。
3. grain=month/range 的 start/end：必须同时存在，开始为月初、结束为月末，且开始不晚于结束；按完整月份展开。
4. points 与 start/end 不能混用；grain=range 不接受 points；不接受 day/quarter/year。
5. 所有月份排序并去重；month 下多个日期落在同月只生成一个分支。
6. 缺时间或缺边界沿用 TIME_UNRESOLVED；非法或不完整月份形状报 REPORT_TIME_UNSUPPORTED。
7. 展开的每个月都必须出现在 partitions；缺任意一项报错，不能使用已有月份子集，也不推测表后缀。

例如 2026-04-01 至 2026-06-30 读取三个月；2026-04-15 至 2026-06-30 拒绝，避免把半个月请求擅自扩大到整月。
编译器不探测物理表是否真实存在或某月是否有数据；目录/数据库可用性由独立校验和未来执行层负责。

## 6. 报表粒度、投影与排序

请求维度先通过 catalog 按名称/code/同义词解析、按业务 code 去重。
请求的维度集合必须与 ReportDef.dimensions 完全一致；不能省略预计算粒度或多加维度。
即使某维度被过滤，也不因此允许静默丢掉该维度。

投影统一为：

1. 当前分表 month_column AS stat_month；单月也保留。
2. 按请求中首次出现的维度顺序，投影编号列和可选展示名称列。
3. 当前分表 value_column AS metric.code，例如 npl_rate AS npl_ratio。

报表记录按唯一粒度直接读取，不生成 SUM/AVG/MAX/GROUP BY。
名称直接取报表行，不是放宽明细的名称分组规则，而是本路径根本不重新聚合。
NULL 指标、零值及同值记录原样保留，不 COALESCE、不乘 100、不 DISTINCT。

最终按 stat_month 和所有维度编号升序排序；多月只在 UNION 外层排序。
所有分支列数、列顺序和别名一致；每个分支都带 `month_column = 'YYYYMM'`，不因为表名带月份就省略过滤。
UNION 必须显式 ALL，不能用默认 UNION 去重。

预计算粒度唯一性由数据源约束或独立质量检查保证；测试库使用联合主键，并验证重复粒度插入被约束拒绝。
不在编译器里通过任意 MAX/去重掩盖违约数据。

## 7. 过滤、Scope 与原子性

### 业务过滤

仅允许登记在该报表粒度中的维度；物理列来自 ReportDef，不回退到明细表维度列或关联表。
只支持 eq/in，复用现有码值转换与 UNKNOWN_CODE；None 值不产生谓词，空 IN 列表产生恒假条件。
不支持的运算符明确报 REPORT_FILTER_UNSUPPORTED，不能悄悄当 eq。

### 表、列权限

先解析全部月份和全部分表，再检查每张实际参与表的 Scope。
未传 Scope 不限制；显式空 Scope 拒绝；任意分表不在表范围内，整个编译失败，不产生部分查询。
报表权限只检查实际报表，不因其由明细预计算就要求访问明细表；也不自动授予报表权限。

每个分支构造后、合并前检查实际物理列：月份、指标、编号、名称、过滤、行策略列。
白名单未配置某表时不限制，显式空白名单表示无可读列。
任意分支列权限不足，整个编译失败；不通过省略名称或月份列规避权限要求。

### 行级策略与零行分支

按 RowPolicy.table 注入对应分支，保留声明顺序；非本次查询表的策略不生成 SQL，不扩大扫描范围。
WHERE 顺序保持“月份 → 业务过滤 → 权限”。
某分表空取值行策略继续按现有契约生成 WHERE 1 = 0；该分支仍在 SQL 中，不抛弃或改用另一张表。
行级过滤使某月返回零行是合法权限结果，区别于表不可访问/列越权导致的整个请求拒绝。
同样，物理分表实际无数据时可返回零行；编译器不连接数据库，不能推断该月应有多少行。

“不可部分成功”指不能吞掉来源解析或表列权限错误；不代表向调用者承诺每个月一定有结果行。

## 8. 编译接线与独立校验

新增聚焦的报表编译模块，分为元数据/月份解析、单表分支构造、UNION ALL 装配三个步骤。
在 compile_intent 解析出业务指标后，根据 source_mode 路由；plain 保持原有来源和形状处理。
返回类型拓宽为 exp.Query，实际仍为原来的 Select 或新增 Union，不改调用方的 SQL 文本接口。

每个报表分支是单表 SELECT，可复用行策略、码值及列权限逻辑，但不让它通过明细 JOIN 来源解析来选表。
复用的若只是字段绑定接口，做小范围调整，不建设通用规划器，也不修改语义目录来临时切换维度。

分支采用独立别名：第一个沿用调用者 alias，之后依次 alias_2、alias_3。
默认是 t1/t1_2/t1_3，各别名在整条查询内唯一；不能在多个分支中反复使用 t1 造成 L4 的列目录覆盖。

每个分支独立检查 FROM 及形状完整性，最终检查 ALL 合并和可渲染性；不能要求 Union 根节点具有 FROM。
L4 仅接收 SQL 文本、独立名字目录、Scope、Intent 等输入，不接收报表编译中间产物。
继续由 R-JOIN-001 拒绝 report/union 的任何 JOIN，明细两表上限不限制合法的三个月 UNION。

## 9. 稳定错误码

| 情况 | stage | code |
|---|---|---|
| 指标未登记报表来源 | symbol_table | REPORT_SOURCE_MISSING |
| 任一月份未登记分表 | symbol_table | REPORT_PARTITION_MISSING |
| 元数据错误或不一致 | type_check | REPORT_CONFIG_INVALID |
| 请求粒度与报表粒度不一致 | intent | REPORT_GRAIN_MISMATCH |
| 非法/部分月份、混用时间写法 | intent | REPORT_TIME_UNSUPPORTED |
| comparison/Top N 等组合 | intent | REPORT_SHAPE_UNSUPPORTED |
| 过滤运算符未支持 | intent | REPORT_FILTER_UNSUPPORTED |
| 任一实际分表无权限 | scope | TABLE_NOT_IN_SCOPE |
| 任一实际物理列无权限 | scope | COLUMN_NOT_IN_SCOPE |

缺时间、未知指标/维度/码值沿用现有错误码。过滤维度已存在但不属于报表粒度时使用 REPORT_GRAIN_MISMATCH。
不得用来自 JOIN 的错误码描述报表分区缺失或月份不合法。

## 10. 验收与交付

### 黄金 SQL

从 G-015 开始新增手写标准答案，至少包括：

- AQ-006 对应的 202604 单月产品不良率，正确来源、不再次聚合。
- 202604~202606 三个月 UNION ALL，保留月份与产品维度，统一外层排序。
- 业务过滤及各分表不同的表列行权限。
- 多分支中某个分支空行策略，保留该分支的恒假过滤。

登记 covers/why_hard，覆盖 R-JOIN-001/C-06、R-PCT-001/C-07、D-04/D-11 等实际规则。
G-001~G-014 不改标准 SQL；AQ-006 的业务预期不改，新增黄金 SQL 可采用满足唯一粒度的直接投影，
不冒称它与旧 GROUP BY/MAX 写法文本相同，业务等价性由 SQLite 结果和主键前提验证。

### 正反例测试

使用独立 SQLite 内存表，包含标准产品表与逾期口径的同名字段表。
验证 LP03 的标准值 0.140700，不混入逾期口径 0.128300；断言实际来源表，不能只比较数值。

覆盖单月、多月、三分表、跨年/闰年、日期去重、保留月份/NULL/零值/重复值、输出排序，
以及粒度、过滤、权限、非法组合和全部稳定错误；元数据无效时不能静默放行。
别名反例使用不同列目录的分表，确保后一个分支不能覆盖前一个分支的错误列引用。

任一月份缺配置、任一分表或列无权限时整个请求失败；行级空结果则保留合法分支结构。
维持原有 JOIN/delta/Top N/名称规则测试，通过原始 14 条黄金用例和演示脚本。

验证命令为 pytest、scripts.check_golden、scripts.validate_cases、ruff check、变更文件格式检查、git diff --check。
不调用模型、不联网、不连接外部数据库。
