# M4.2：黄金集扩展到 30 条

日期：2026-11-25。本文记录 M4.2 的设计与验收边界。

## 目标与边界

把 `eval/golden` 从当前 26 条扩到 30 条，用手写 SQL 钉住已有编译器能力中尚未被黄金集充分覆盖的形状与陷阱。黄金集仍只回答“给定 Intent，编译器是否产出正确 SQL”，不承担自然语言理解、数据缺失解释或真实模型质量评估。每条新增用例都必须同时包含手写 SQL、`Intent`、`shape`、`why_hard`、`covers` 和专项测试。

本轮不新增业务表、指标或报表配置。`AQ-006` 已由 `G-015` 覆盖，不重复添加；`AQ-007` 的核销表语义当前不在演示语义目录中，贸然加入会把 M4.2 变成语义层扩展；`AQ-009` 的缺失快照和 `AQ-010` 的广告投放不可答属于 M4.3/M4.4 行为评测，不伪造黄金 SQL。

## 新增用例

### G-027：普通明细不良率

使用 `不良贷款率`、`2026-04-30`、`plain`，不带维度。关联评测 `AQ-003`。黄金 SQL 固定分子五级分类 `30/40/50`、分母同一时点全行余额、`NULLIF` 零保护，并保持 0～1 小数，不乘 100。覆盖 `C-07`、`R-PCT-001`、`D-09`。

### G-028：机构范围内不良率

使用同一指标和时点，增加登记机构过滤“渝北支行”，并附带 `Scope` 行策略只允许 `B001/B002`。验证业务机构过滤与权限行策略都在分子和分母的同一聚合上下文中生效，不能把分母扩大为全行，也不能按逾期天数替代五级分类。覆盖 `C-04`、`C-07`、`R-PCT-001`、`D-01`。

### G-029：报表单月产品过滤

使用 `不良贷款率`、`source_mode=report`、`2026-04-30`、产品维度和产品过滤“消费贷款”。验证报表分支只投影已登记月份分表，业务过滤落到报表编码列，直接读取预计算比例而不再次聚合或回退到明细表。覆盖 `C-04`、`C-06`、`R-JOIN-001`、`D-04`。

### G-030：普通明细比率的列权限拒绝形状

使用 `不良贷款率`、`2026-04-30`，对明细表提供不含 `current_balnc_cny` 的显式列白名单。该用例的黄金文件记录编译器的拒绝预期，而不是伪造一条可执行 SQL：门禁加载器增加 `expected_compile_error`，对这条用例断言 `stage=scope/code=COLUMN_NOT_IN_SCOPE`。它把百分比指标需要分子、分母两组列的权限边界纳入黄金配置；不会让 L4 或 L5 执行不完整查询。覆盖 `R-PCT-001`、`COLUMN_NOT_IN_SCOPE`、`C-07`。

## 门禁契约调整

- `eval/golden/cases.yaml` 仍禁止自动刷新；G-027～G-029 走现有 SQL 比对和 L4 校验路径。
- G-030 是唯一预期编译失败的黄金用例。加载器严格要求 `expected_compile_error` 仅包含 `stage` 与 `code`，没有该字段的用例不能编译失败；黄金 SQL 文件不为 G-030 提供可执行答案，避免把拒绝路径伪装成 SQL 黄金。
- `check_golden` 的总数变为 30，成功数按“通过预期”计算；报告须显示编译拒绝用例是预期通过，不把它统计成引擎失败。评测集交叉覆盖从 7/10 保持不变，`AQ-003` 新增对照后为 8/10；`AQ-007`、`AQ-009`、`AQ-010` 继续列为无黄金 SQL 对照。
- 现有 G-001～G-026、黄金比对归一化、L4 规则和旧评测文件不改。新增测试覆盖配置纪律、成功比对、预期编译错误、未知错误码和不应执行 L4/L5 的边界。

## 验收

运行全量 pytest、Ruff 和黄金门禁。目标是 30/30 黄金用例通过，原有 1511 项测试无回归，并明确报告没有调用真实模型、没有访问外部业务数据库。AQ-003 的结果数值仍以现有 fixture/评测手工标准为准；黄金集不根据当前引擎自动生成。
