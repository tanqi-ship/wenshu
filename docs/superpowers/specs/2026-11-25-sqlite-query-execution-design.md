# M3.4：SQLite 业务只读执行与端到端接线

日期：2026-11-25。本文定义待实施的设计，不代表 L5 已交付。

## 目标与范围

在严格模型回放下，从 AQ-001 的原始问题得到与既有评测一致的业务结果，并跑通跨请求补答后的同一条执行路径。只做本地 SQLite、引擎入口与 CLI；不做 API、前端、认证、多数据库适配、真实模型验收或 M4 的可答性分类。保留旧演示、黄金 SQL、AQ 评测和会话状态契约。

采用独立 SQLite 执行器与薄流程编排。只在演示脚本里执行虽然改动小，但无法形成可重用、可独立测试的执行层；现在引入多数据库抽象则超出本轮范围。

## 流水线与权限

- 新入口复用 `ClarificationService.start/reply`。仅 `slots_complete` 且带有 `Intent` 时进入编译、校验、执行。等待补答、预算耗尽或要求重启时原样返回会话状态，不编译、不打开业务库；查看会话也不执行查询。
- 可信调用方每次显式提供 `Scope`；不从用户文本、模型输出或会话快照恢复授权。编译注入行权限，校验使用同一 `Scope`、本次 `Intent` 和物理目录；两层均使用 SQLite 方言。SQLite 只读限制不替代数据权限。问题中出现“全行”不扩大权限。
- 新入口仅在 L4 没有 `Problem` 时执行同一次校验所检查的 SQL，不改写，不接收 CLI 或模型提供的 SQL。此保守放行规则不改变旧 `ValidationResult.ok` 行为。
- 区分澄清、编译失败、校验失败、执行失败和查询成功。保留现有编译和校验代码，不调用模型修复 SQL，不自动重试。会话照常先提交状态；查询失败不会回滚已完成的澄清，也不通过重放补答重新执行。此阶段需重试时重新发起问题。

## 执行契约

- 每次查询以 SQLite URI `mode=ro` 打开可信配置指定的已有文件，并启用 `query_only`。再使用 SQLite 授权回调允许查询所需的读取、选择和明确列出的内建函数，其他动作默认拒绝，包括写入、附加库、加载扩展和运行时 PRAGMA。执行器是内部接口，不提供任意 SQL 查询能力。
- 返回列名、按列位置排列的数据行和 `truncated`。默认上限 100 行，可信配置可设为 1 到 1000 行。最多从结果读取上限加一行；恰好到上限不算截断。不改写 SQL，不保证无 `ORDER BY` 时的顺序。零行是成功，聚合 `NULL` 原样返回；行数上限不是扫描量或字节上限。
- 默认查询预算 2 秒，使用单调时钟和 SQLite progress handler 检查执行及取数，另设不高于预算的锁等待上限。超时不返回部分数据；查询预算不承诺覆盖连接建立、操作系统阻塞或硬实时中断。所有路径释放游标和连接。
- 执行错误使用独立机器码：`EXECUTION_INVALID_CONFIG`、`EXECUTION_DB_UNAVAILABLE`、`EXECUTION_DENIED`、`EXECUTION_TIMEOUT`、`EXECUTION_FAILED`。仅本次预算触发中断或检测到超出预算时报告超时；其他驱动错误不冒充超时。对调用方不暴露绝对路径或原始驱动信息。

## 演示与验收

- 新增独立 SQLite 造数入口，与会话库分开；执行器不建库。以仓库 PostgreSQL fixture 为来源，只投影本轮所需列和快照，保留 1、2、4 月和多个机构，使端到端测试能发现跨期累加或作用域过滤错误。用实际造数表建立演示校验目录，不承诺覆盖未造数的报表或维度表。
- 新增严格离线 CLI，演示直接问数与跨进程补答。AQ-001 使用原题“2026年4月末全行贷款余额是多少？”及独立手写回放键，不用题面不同的 EX-001 代替；补答复用 M3.3 固定样本，不改旧 cassette。回放未命中直接失败，不联网。
- AQ-001 无追问；全行结果与既有评测预期 `20210000.00` 一致，`B001` 行权限下结果为 `12660000.00`，显式空表权限阻止执行。跨进程补答验证使用补答当次 `Scope`，不沿用上次授权。
- 测试澄清、编译失败、校验失败时执行器零调用；验证只读、缺库不建库、零行、恰好到上限、超限、超时无部分结果及资源释放。实施完毕后运行默认测试、Ruff 和 26 条黄金 SQL 门禁；离线结果不代表真实模型效果。
