## 1. 已确认的目标

机构业务输入只接受已登记的全称、简称或编码；必须能唯一确认，不猜测、不模糊匹配，不自动包含下辖机构。

- 正常输入“渝北支行”或登记简称“渝北”，均转换成登记编码 B001。
- 直接输入登记编码 B001，仍精确查询 B001，不二次改写或改为前缀查询。
- 未登记机构明确报错；配置歧义不能靠第一条匹配、最长匹配或某个候选得分来裁决。
- 缺少严格维度的码值配置时报告配置缺失，不能透传成永远匹配不到的条件，让未知机构看起来像空/零业务数据。
- 财务/管户的现有默认口径保持不变；“本机构”不自动扩成机构树、名称前缀或下辖机构集合。
- 权限仍由 Scope 输入，业务机构名不能覆盖或移除权限条件。

## 2. 方案选择

| 方案 | 收益 | 不足 | 结论 |
|---|---|---|---|
| 仅 L4 禁止 LIKE | 改动小 | 缺配置透传、别名歧义和非 LIKE 的变形匹配仍可漏过 | 不采用 |
| 语义层精确解析 + 编译器统一限制 + 独立 L4 规则 | 输入与 SQL 双向守住，复用现有高基数标记和条件接口 | 需明确登记规范、来源识别和规则责任边界 | 用户已同意 |
| 完整机构主数据/机构树服务 | 可覆盖层级、有效期和归属变更等 | 需要额外服务和业务模型，不符合当前学习项目范围 | 本轮不做 |

本轮不调用模型、embedding、数据库或外部检索来补机构候选，不建设通用血缘平台。

## 3. 首版范围

### 支持

- 复用 DimensionDef.value_kind="high_cardinality"，机构类维度显式启用严格值解析。
- 全称、显式登记简称、已登记存储编码的精确识别；多条别名指向同一编码合法。
- 业务过滤 eq/in、None 不过滤、空 IN 恒假；保持既有码值翻译和权限注入接口。
- 在 plain/delta/Top N/受限 JOIN/share 中复用同一严格解析；report/union 仅在报表声明了对应机构粒度时适用。
- R-ORG-001 独立检查受保护机构字段上的匹配条件，包括 SQL 表别名和派生列改名。

### 不扩展

- 自然语言机构抽取、自动判断财务/管户口径、自动机构树下钻、历史归属、递归和多跳 JOIN。
- 模糊简称生成、错别字修复、拼音相似、大小写猜测或去除内部空白后重新匹配。
- 任意机构目录的自动同步、真实主数据唯一性证明、通用 SQL 等价证明或完整权限系统。
- 借机构规则放开既有报表粒度、占比、Top N、公式或多表边界。

未声明严格标记的普通 coded 维度继续旧契约；本轮不会顺带改变产品等所有维度的值解析。

## 4. 机构登记与精确识别

### 数据形态

继续使用 code_map[dimension.code] 的字符串别名 → 存储编码映射，不增加数据库或别名服务。
登记编码来自该映射的值集合；需要只登记编码时，可显式写“编码 → 同一编码”。

同一维度内，别名和编码共享一个精确 token 空间：

```yaml
org:
  渝北支行: B001
  渝北: B001
  江北支行: B002
  江北: B002
```

B001、B002 作为登记值也可直接输入；不要求每个编码重复写一个自映射。
一个别名若同时是另一个机构的编码，不能优先使用“键命中”来掩盖冲突。

### 规范化边界

严格值仅移除输入两端空白；不删除内部空白，不 casefold，不 Unicode 兼容折叠，不展开通配符。
代码 B001 与 b001 不自动等价；若确有合法异体或简称，维护者须显式登记。
机构值使用字符串；eq 的列表/字典、IN 中的嵌套容器、数值或布尔值等不当作机构名称猜测，按未知值拒绝。
None 作为整个 Filter.value 时仍不产生条件；IN 中的 None 不是“无过滤”，应拒绝。

映射键和值必须是非空字符串，存储编码不能带首尾空白。别名按同一 trim 规则建索引。
每个 token 收集全部命中的编码，不能提前返回：零个为未知，一个为成功，多个为歧义。
例如“ 渝北 ”与“渝北”分别指向 B001/B002，或别名 B001 指向 B002 而 B001 又是其他登记值，均须拒绝。
相同 token 的多项都指向同一编码可以合并，不误报歧义。

### 配置校验与层间依赖

新增聚焦的 semantic/exact_values.py，处理索引、配置检查和带原因的中立解析异常；不依赖编译器或 sqlglot。
SemanticCatalog.build 校验 value_kind 的合法枚举，以及已经提供的严格映射的类型、内容和歧义。
允许仅声明维度但暂未给映射，显式空映射也允许加载；一旦业务过滤实际需要解析该维度的非空值，
缺失映射或空映射均以 EXACT_VALUE_MAP_MISSING 报告缺配置，而不是按未知机构或透传处理。
这样不会为了查看目录或只按机构分组，就要求枚举全部机构，也不会让实际名称过滤绕过登记。

直接构造/replace 目录绕过 build 时，编译期对参与值解析的维度重新验证，不能复活“缺配置透传/第一个匹配”的旧行为。
编译器将中立异常转为 CompileError；语义层不反向 import compiler.errors。

## 6. L3 编译接口与运算符

在条件共用接口 build_filter_condition 中，对实际需要过滤的严格维度只允许 eq/in。
不能把 gte/lte/between 或直接构造的 like 等运算符偷偷解释成 EQ。
JOIN/share/report 等分支已有更具体的形状或过滤拒绝规则时保留它们；不为了统一错误码而放宽原分支。

- eq：一个字符串机构值，解析为存储编码后生成 Column = string literal。
- in：单值或一层字符串集合，逐项精确解析，任意一项未知/歧义都使整条失败；不删除失败项继续查询。
  单元素沿用既有 EQ 简化，多个元素沿用 IN；不在本轮改变集合输出顺序或旧 SQL。
- None：不解析该过滤、不增加来源；空 IN：仍生成恒假，不为一个没有实际值的空集合强制读取码值表。
- 只有实际值需要翻译时才访问登记；表/列权限和来源形状仍按各编译分支既有规则检查。

最小迁移是在 SemanticCatalog.code 和共用条件接口中接线；不复制一套机构逻辑进五个编译分支，
不修改公式、机构默认 LevelDef、报表固定粒度或 Scope 行策略来临时满足机构输入。

### 非结构化的 Intent.org

本轮机构条件以 filters 为准，不新增自然语言解析或自动口径判定。
非空 Intent.org 不能继续在普通/报表分支静默丢失：公共编译入口明确报 ORG_CONTEXT_UNRESOLVED，要求先规范到 filters。
占比路径已有 SHARE_CONTEXT_UNRESOLVED 保持原契约；不让改错误码掩盖旧的显式拒绝。
即使 org 与某个 filters 看起来相同，本轮也不自动合并、覆盖或推断其归属口径。

## 7. 权限保持独立

Scope.row_policies 是授权侧提供的存储值，不是用户口语，不能拿新的业务别名解析器重新解释或删除它。
例如业务机构“渝北”解析为 B001，同时权限是 org_no IN ('B001','B002')，两条条件均按原顺序保留，取交集。
权限中的 B002 不因为某个业务维度目录未登记它就被改写；授权主数据完整性属于权限提供方。

空行策略继续恒假，未使用表的策略不引入 JOIN；表/列白名单契约不变。
R-ORG-001 检查匹配方式，不替代 R-RATIO-001 对占比行策略的保留检查，也不声称能证明所有查询没有权限遗漏。

## 8. L4 保护字段的独立配置

在 ValidationPolicy 末尾追加 org_columns: Mapping[str, frozenset[str]]，表名使用 schema.table 全限定名。
它是可信校验策略，不由 Intent 提供，也不从 L3 的维度绑定、索引或编译计划生成。
构造时复制并冻结配置，校验合法表/列标识符；无效配置 ValueError，不能渲染任意 SQL。

默认演示策略显式保护：

- public.qa_loan_acc_detail：org_no、org_nm、accounting_org_no、higher_level_org_no、higher_level_org_nm、
  belong_to_org_no、belong_to_org_nm。
- public.dim_org：org_no、org_nm、parent_org_no。

策略可登记物理目录尚未暴露的列；名字是否存在仍由独立 Catalog 校验，策略不是补造 schema。
同名表的 schema 根据 Catalog 解析，不能把不同 schema 的表混成一个；缺省 schema 必须能唯一确认。
若使用 main 或其他 schema、改名列或新增报表机构列，调用者必须显式配置相应保护范围。
空映射表示调用方明确不配置此规则的保护字段，不是系统自动猜机构列；只有可信策略可作此选择。
不因为任意列含 org 字样就拦截，不扫描字面量里的“支行”来猜业务含义。

L4 不接收 code_map，不做第二遍机构名称翻译；它能验证匹配形状，不能据此断言编码已登记、全称唯一或口径选对。
这些语义由 L0/L3 和独立黄金/结果用例保证。

## 9. R-ORG-001 的匹配规则

新建 validation/org.py，从 SQL AST 和独立保护策略检查，不 import 编译器或 SemanticCatalog。
即使没有 Intent 也要检查匹配方式，不能靠不传机构意图绕过。

### 允许

- 受保护字段直接 EQ 字符串字面量，允许 org_no = 'B001' 与 'B001' = org_no 两种方向；
  或直接 IN 一层非空字符串字面量集合。这里的正向条件指未被 NOT 等否定，不限制 EQ 两侧顺序。
- 直接列 = 直接列的等值关系，用于正常 JOIN；关系方向/基数是否安全仍属于原有编译边界。
- 多条合法精确条件的 AND/OR；无机构列的恒真/恒假条件仍按其他规则处理。
- 编号投影、按编号分组/排序和 MAX(机构名称) 展示；正常金额聚合不误报。
- 字符串里真实的 % 或 _ 在 EQ/IN 中没有通配语义，不能单凭字符存在就禁止。

### 拒绝

- LIKE/ILIKE/NOT LIKE、正则、前缀/后缀/包含、INSTR/STRPOS 等变形匹配。
- 对受保护值先 LOWER/UPPER/TRIM/SUBSTRING/REPLACE/CONCAT/CAST 等再匹配，
  即使函数被藏在派生投影后改名，也不能因最终表面是 EQ 就放行。
- 受保护值的 BETWEEN、大小比较、不等、NOT EQ/NOT IN、IS NULL/IS NOT NULL、子查询 IN 或计算值列表。
  这些不在首版精确机构筛选能力内；非机构字段的对应操作不受此规则影响。
- 机构字符串编码按数值隐式匹配，或把计算值当作已登记字面量；这不能证明保持了原始编码。

检查 WHERE、HAVING、JOIN ON、CASE WHEN 以及能影响条件的布尔/函数表达式；
不能只搜 SQL 文本里的 LIKE，也不能把名称仅用于展示误当成机构筛选。
正常 org_no = dim_org.org_no 的 JOIN 等值键不因列名受保护而被拒绝。

## 10. 别名、派生列与保守边界

此模块只实现保护列所需的局部来源追踪，不复用现有名字校验器的全局别名表，不做通用业务血缘平台。
必须按查询作用域解析，正确处理嵌套查询复用别名、CTE、简单 UNION ALL 的输出位置与重命名。

- 直接物理列由 Catalog 确认表身份，再查 org_columns；显式未受保护表的同名列不应误报。
- 直接列的投影/改名保留“精确来源”状态，允许外层对改名后的机构码 EQ/IN。
- 保护列经过字符串转换、表达式或名称 MAX/MIN 后输出，标记“已变换”；只展示仍合法，但用其再作匹配须拒绝。
- Window 的 PARTITION BY/ORDER BY 是控制表达式，不把它们当成输出标识符来源；
  ROW_NUMBER/RANK 等排名输出不因按机构编号打破并列就变成机构值。
  COUNT/SUM/AVG 等数值统计输出也不作为机构标识符传播；其内部条件仍单独检查。
- 多分支来源按输出位置合并；任一来源受保护不能因其他分支是普通值就洗掉保护，来源混合不能假装精确传递。
- 单源 SELECT * 可依据独立 Catalog 展开来源；多源同名、递归 CTE、相关作用域或其他无法确认的机构匹配，
  必须报告无法确认，不能把“没追踪出来”当作普通非机构字段放行。
- 对无法确认且涉及保护字段或受保护关系输出的谓词 fail-closed；不因完全无关列的复杂表达式一律拒绝。

至少覆盖编译器当前产生的单表、两表 JOIN、Top N 三层、share 三层和报表/UNION 结构。
不全局改写或放宽现有名字、来源、子查询、排名和占比规则。
任意自定义函数若能改变机构值且其输出被用于匹配，应传播为已变换/未确认，而不是仅维护少量禁用函数名。
本轮不声称通过此局部追踪解决全部未知 SQL 及既有名字校验限制。

## 11. 稳定错误与归因

| 场景 | stage / 规则 | code |
|---|---|---|
| 严格机构值未登记，或输入不是单个字符串 token | symbol_table | UNKNOWN_CODE（沿用） |
| 严格维度需要解析值但未配置映射 | type_check | EXACT_VALUE_MAP_MISSING |
| 值类型标记/映射格式非法 | type_check | EXACT_VALUE_MAP_INVALID |
| 别名/编码 token 指向多个存储值 | symbol_table | AMBIGUOUS_CODE |
| 严格过滤不是 eq/in，且无分支更具体错误 | intent | EXACT_FILTER_UNSUPPORTED |
| 非占比公共入口收到未规范 org | intent | ORG_CONTEXT_UNRESOLVED |
| 占比入口收到未规范 org | intent | SHARE_CONTEXT_UNRESOLVED（沿用） |
| 受保护机构值使用非精确或变换匹配 | R-ORG-001 / error | ORG_MATCH_NOT_EXACT |
| 机构匹配无法唯一确认物理/派生来源 | R-ORG-001 / error | ORG_MATCH_SOURCE_UNRESOLVED |

EXACT 系列属于可复用严格值机制，当前以机构维度落地，不把普通 coded 维度顺带改成严格登记。
L0 加载已给的坏配置时 ValueError；手工目录绕过加载器后，L3 转成上述稳定错误。
错误不能通过跳过某个 IN 值、回退名称列、改默认机构口径、去掉 Scope 或猜表名恢复成“成功”。

## 12. 黄金集与验收

从 G-023 起新增手写标准 SQL，至少包括：

- 登记机构简称解析成精确编码，不包含前缀相似或下辖机构。
- 登记全称/编码混合 IN，每个值都精确解析，不允许部分成功。
- 正常 JOIN 机构键及上级机构精确过滤，不误伤旧关联契约。
- 机构业务别名与 Scope 权限、占比上下文结合，条件求交且占比分母不被错误扩张或缩小。

登记 covers/why_hard，覆盖 R-ORG-001、D-06 及实际涉及的权限/占比规则，不为凑覆盖冒称 C-09 已由此自动选对口径。
G-001~G-022 SQL 不变；AQ-002 的本级机构语义不改，不将其扩为下辖网点汇总。

### 正反例矩阵

- L0/L3：全称、登记简称、直接编码、空值/空 IN、未知编码、伪造前缀、歧义别名、别名撞编码、
  缺映射、非法映射、非字符串值、全批次拒绝、严格与 coded 对照、多个机构口径、外部权限值不被重译。
- SQLite 独立数据：B001“渝北支行”=100，B0019“渝北支行营业部”=200，O001“渝北龙溪分理处”=300。
  精确选择 B001 只能得到 100，不能得到代码前缀 B001% 的 300 或名称前缀 渝北% 的 600；
  不能自动把 O001 纳入本级。
- 特殊字符名称若已登记，EQ/IN 按原值安全匹配；未知的带通配符输入仍因未登记而失败。
- L4：直接、反向 EQ、IN、JOIN 键、显示 MAX、CASE 中模糊条件、ILIKE/正则/函数变形、否定/区间、
