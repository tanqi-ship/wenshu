# M2.5：同口径整体分母的占比查询设计

日期：2026-11-23

状态：用户已确认；实现及本地验收完成（2026-11-23）。
基线：`b2bb6eb`，M2.4 已提交；562 项测试、18/18 黄金用例通过，M2 完成 4/6。

## 1. 已确认的目标

给定结构化 Intent，计算“某维度下各组的同一指标，占当前上下文整体指标的比例”。
例如“2026 年 4 月末，渝北支行各产品贷款余额占比”：

- 分子是渝北支行某个产品的贷款余额。
- 分母是同一时点、同一机构条件、同一权限范围内，所有产品的贷款余额。
- 即使只展示小微企业贷款，也不能把分母缩成小微企业贷款自身。
- 分子分母使用同一指标公式；不良贷款余额占比的分母是整体不良贷款余额，不是整体贷款余额。
- 分母不能突破用户的表、列或行权限。“整体”不是未经授权的全库或全行。

占比不等于不良率，也不等于增长率。已有 `comparison=rate` 不改为本轮占比语义。

## 2. 方案比较与选择

| 方案 | 优点 | 代价与风险 | 结论 |
|---|---|---|---|
| 分组聚合 → 窗口整体和 → 外层展示过滤 | 只读取一个受权限约束的数据集合，分母不会被外层展示过滤缩小；符合现有 Top N 的分层包装方式 | 需要明确每一层职责及独立校验的规范形状 | 用户已同意采用 |
| 分子、分母分别聚合后合并 | 计算意图直观 | 重复维护过滤与权限，容易口径漂移；还需处理额外来源及子查询规则 | 本轮不采用 |
| 将每种占比单独登记成业务指标 | 少量固定场景简单 | 维度和对象增加时需要大量配置，不适合通用拆分 | 本轮不采用 |

不建设通用查询规划器，不把计算放到尚未实现的 L5，不调用模型产生 SQL。

## 3. 首版范围与明确拒绝项

### 支持

- `source_mode=plain`，实际物理来源只有一张明细表。
- 单个月末快照；请求给出具体日期，不解析自然语言。
- 一个占比维度，按业务编码去重后必须与请求维度一致。
- 顶层普通 SUM 的可加总金额指标，包括 SUM(CASE WHEN ... THEN 金额 ELSE 0 END)。
- 同表上下文过滤及占比维度的 eq/in 展示过滤，精确码值转换。
- 与现有契约一致的表、列、行权限，包括显式空 Scope 及空行策略。

### 不支持

- JOIN、多表公式、报表来源、UNION、Top N、delta/yoy/mom/rate 等组合。
- 多个拆分维度、每个机构内再按产品的分区占比、多个月份、日/区间/季度/年度占比。
- AVG、COUNT、SUM DISTINCT、已有比率、窗口公式、子查询公式及嵌套聚合。
- 按名称分组、过滤后重新归一化、自动补缺失产品或缺失时点。
- 未结构化的机构语义、跨权限求整体、自动推断不同业务维度其实是同一粒度。

这些情况显式报错，不忽略占比请求，不回退到普通金额查询或报表查询。

## 4. 意图结构与兼容性

新增纯数据结构 `ShareSpec(dimension: str)`；Intent 末尾追加可选 `share: ShareSpec | None = None`，
保留已有字段含义和位置参数顺序。ShareSpec 是业务语义，不携带 SQL、物理列、别名或窗口配置。

配置示例：

```yaml
metric: 贷款余额
source_mode: plain
time:
  grain: month_end
  points: ["2026-04-30"]
dimensions: [产品]
share:
  dimension: 产品
filters:
  - dimension: 机构
    value: 渝北支行
  - dimension: 产品
    value: 小微企业贷款
```

- `share` 缺省或为 null 时完全沿用旧路径；既有 G-001~G-018 SQL 不变。
- share 只接受映射，且只接受 dimension 键；空映射、空名称、字符串/布尔值和未知键在加载时 ValueError。
- dimension 接受业务 code、名称及既有同义词，通过 SemanticCatalog 解析。
- `Intent.dimensions` 按业务 code 去重后只能有一个维度，且必须与 ShareSpec.dimension 相同；不自动补维度。
- `Intent.org` 尚不是现有编译器的完整机构条件接口。本轮机构条件须放入 filters；非空 org 显式报
  SHARE_CONTEXT_UNRESOLVED，不能无声忽略或自行猜测机构粒度。这不代替 M2.6。
- 手工直接构造 Intent 绕过加载器时，L3 仍对 share 类型、空维度及组合做防御检查。

## 5. 时间与可加总指标边界

### 时间

只接受 grain=month_end，points 按具体日期去重后恰好一个，且该日期确为月末。
不允许 points 与 start/end 混用，不从 start/end 自动补点；不猜当期、不回退最近有数据的日期。
先拒绝非 month_end 粒度或任何 start/end 边界，报 SHARE_TIME_UNSUPPORTED；
缺时间，或 month_end 无边界也未提供点时，沿用 TIME_UNRESOLVED。
同一日期重复声明可以去重，两个不同月末明确拒绝。
时间条件使用 ValidationPolicy.snapshot_column，位于物理表的最内层 WHERE。

### 指标

- 复用严格公式解析与列绑定，但必须确认根节点是普通 SUM。
- 拒绝 DISTINCT、窗口、子查询、嵌套聚合；MetricDef.is_percentage 为真时也拒绝，即使公式表面以 SUM 开头。
- 顶层 SUM 是本轮的可加总配置契约，不是编译器证明了业务口径正确；单位和公式由知识维护者负责。
- 所有公式列必须可以确认来自当前主表。裸列补主表别名；实际表名/主表别名可规范化，未知限定名不放行。
- 不借本轮扩大 COUNT、复杂算术或已存比例的可加总支持范围，不修改旧 delta 的既有契约。

## 6. 过滤的两种职责

先解析维度 code，再划分过滤；不能靠中文字符串或物理表名猜测。

| 条件 | 所在层 | 是否影响整体分母 |
|---|---|---|
| 快照时点 | 最内层物理 WHERE | 是 |
| 非占比维度的业务上下文，例如按产品占比时的机构 | 最内层物理 WHERE | 是 |
| Scope 对实际表的全部行策略 | 最内层物理 WHERE | 是，绝不移除 |
| 占比维度的业务取值，例如只看 LP03 | 最外层 WHERE | 否，只决定展示哪些已计算组 |

同一产品列既可能有业务过滤，也可能有行权限：业务过滤外移，权限仍在最内层。
不能按“所有 prd_no 条件”统一删除或统一外移。

- 两类业务过滤均只支持 eq/in；非 None 的未支持运算符直接报错，不能沿用旧普通过滤的等值兜底。
- 复用既有精确码值转换，未知码值 fail-closed，不支持 LIKE 或模糊匹配。
- value=None 不产生条件，也不为该过滤额外解析维度或引入来源。
- 空 IN：展示过滤在最外层生成 1=0；上下文过滤在最内层生成 1=0。两者都返回零行，不伪造一行 0%。
- 多条展示过滤按原顺序用 AND 合成；上下文过滤及权限也分别保持各自输入顺序。
- 若一个不同业务 code 的上下文过滤实际绑定到占比编号列，首版不能可靠区分上下文与拆分，
  报 SHARE_FILTER_UNSUPPORTED，要求明确配置；不把它当作绕过整体分母规则的别名通道。

## 7. 三层 SQL 与输出契约

### 第一层：分组金额

在唯一物理表上应用“时间 → 上下文业务过滤 → 本表行权限”，按占比编号列 GROUP BY。
名称使用 MAX，只用于展示，不参与分组。投影为编号、可选名称、原 metric.code 金额。
不应用占比维度的业务取值过滤。

### 第二层：整体金额

读取第一层所有组，显式传递输出列，并计算：

```sql
SUM(share_groups.loan_balance) OVER () AS total_value
```

窗口没有 PARTITION BY、ORDER BY 或 frame，避免变成组内分母或累计值。
本层没有 WHERE、HAVING、LIMIT、DISTINCT，不提前减少分组。

### 第三层：展示与除法

显式输出维度编号、可选名称、metric.code、total_value、share；不使用通配符。
原 metric.code 是分子金额，total_value 是相同度量的整体金额，share 是小数比例。
物理输出别名大小写不敏感地唯一，total_value/share 为保留衍生输出名，冲突即拒绝。
应用外移的展示过滤，最终按维度编号升序排序；不增加快照选择或重新聚合。

示例 SQL（示例采用无额外行权限的 Scope 输入；实际权限按第 8 节注入）：

```sql
SELECT
  share_totals.prd_no,
  share_totals.prd_nm,
  share_totals.loan_balance,
  share_totals.total_value,
  1.0 * share_totals.loan_balance / NULLIF(share_totals.total_value, 0) AS share
FROM (
  SELECT
    share_groups.prd_no,
    share_groups.prd_nm,
    share_groups.loan_balance,
    SUM(share_groups.loan_balance) OVER () AS total_value
  FROM (
    SELECT
      t1.prd_no AS prd_no,
      MAX(t1.prd_nm) AS prd_nm,
      SUM(t1.current_balnc_cny) AS loan_balance
    FROM qa_loan_acc_detail AS t1
    WHERE t1.etl_dt = '2026-04-30' AND t1.org_no = 'B001'
    GROUP BY t1.prd_no
  ) AS share_groups
) AS share_totals
WHERE share_totals.prd_no = 'LP03'
ORDER BY share_totals.prd_no;
```

编译结果可以采用方言对应的显式浮点转换实现等价除法；SQLite 必须用整数原始金额测试非整除结果，
不能因为测试数据碰巧是 REAL 就误以为整数除法已经安全。黄金 SQL 的实际写法在实现时手工确定，不由编译器反向生成。

内部派生别名确定性分配，避开调用者 alias 和实际物理表标识，避免独立 L4 把物理别名误认成派生表。
继续返回 exp.Query（实际根为 Select），SQL 文本接口不变；逐层检查 FROM 和最终可渲染性。

## 8. 权限与 NULL/空结果语义

### 权限

- scope=None 不限制；显式空 Scope 拒绝；唯一实际表必须可见。
- 外层包装前，检查最内层所有物理列：时间、编号、名称、指标参数、上下文和行策略引用列。
  展示过滤使用的编号已经在物理分组投影中，不能借移到外层绕开列权限。
- 缺省表列白名单不限制；显式空白名单拒绝。不通过 COUNT(*)、SELECT * 或隐藏列绕过。
- 只有当前表的 RowPolicy 生效；未使用表的策略不引入 JOIN，不要求该表权限。
- 行权限在分组之前只应用一次；空值策略生成 1=0，返回零行，不保留无权组或伪造 0% 行。
- 同一占比列的权限必须留在最内层，不能连同展示过滤一起外移。分母仅汇总可见组。

### 数值和数据缺失

- 分母为 0 或 NULL：share 为 NULL；保留实际存在的组及其金额，不对最终占比 COALESCE 成 0。
- 某组金额为 NULL：分子与 share 保留 NULL，整体 SUM 使用数据库的标准 NULL 语义。
- 数据源没有满足上下文/权限的行，或展示对象不存在：返回零行，不补产品、不补时点。
- 允许保留源数据中的零、负值和名称 NULL；不截断、不取绝对值。
  有负金额时比例可能不在 0~1，不能强行钳制；“返回小数比例”不代表编译器保证所有金额非负。
- 占比不乘 100、不做展示层 ROUND；百分号及显示精度留给下游。
- 无展示过滤且整体非零、数据适用时，所有组占比之和应约等于 1；有展示过滤时不要求展示行之和为 1。

## 9. L3 接线和稳定错误

在解析业务指标之后、report/union 和普通明细分支之前识别非 None 的 share 请求。
新建聚焦的 compiler/share.py，负责意图检查、唯一来源绑定、条件分流、三层装配。
可将本轮已确认的元数据放进模块内私有解析结果，不把该中间产物传给 L4。
复用精确码值、行策略、公式解析和物理列权限的小接口；不修改目录来临时替换字段或过滤。

| 情况 | stage | code |
|---|---|---|
| share 直接构造类型错误，或混用来源/多表/JOIN/Top N/对比 | intent | SHARE_SHAPE_UNSUPPORTED |
| share 缺少明确拆分维度 | intent | SHARE_DIMENSION_REQUIRED |
| 请求维度不唯一或与 share.dimension 不一致 | intent | SHARE_DIMENSION_MISMATCH |
| 非单个月末时点、点与区间混用、月末日期不真实 | intent | SHARE_TIME_UNSUPPORTED |
| 非空 Intent.org 未规范到 filters | intent | SHARE_CONTEXT_UNRESOLVED |
| 过滤运算符或同列多语义绑定不支持 | intent | SHARE_FILTER_UNSUPPORTED |
| 公式不是本轮允许的可加总 SUM | type_check | SHARE_METRIC_NOT_ADDITIVE |
| 编号/名称/指标/衍生输出名冲突 | type_check | SHARE_OUTPUT_COLLISION |

未知指标、维度、码值、缺时间、缺来源、维度口径缺失、表列越权和非法公式沿用既有错误。
拒绝外部公式限定名不能仅在 scope.columns 非空时才生效；无 Scope 时也必须能确认唯一来源。
先检查 share 组合边界，不让 report/Top N 等分支无声忽略 share。
无 share 的旧输入不改 SQL，不改变已有负例的错误码。

## 10. 独立 L4：R-RATIO-001

L4 只接收 SQL 文本、独立名字目录、Intent、Scope 和 ValidationPolicy；不接收或调用 L3 的拆分计划、
条件构造器、公式解析结果或别名常量。新规则只在 Intent.share 非 None 时触发，不影响既有普通查询。

本轮校验明确支持的三层规范形状，不建设通用 SQL 等价证明。内部别名可不同，不靠字符串拼 SQL 匹配。

至少检查：

1. 唯一物理表、单个编号分组和三层数据流；不夹带 JOIN、UNION、第二来源、DISTINCT、LIMIT 或额外分组。
2. 整体列确实是对第一层分组金额做 SUM 的空窗口；无 PARTITION/ORDER/frame，计算前没有中间筛选。
   不能仅凭查询中出现过任意窗口函数就认定整体分母正确。
3. 最外层 share 使用同一分子金额和整体列，除数有 NULLIF(total_value, 0)；不能改成自身金额或累计值，
   不能乘 100、COALESCE 或先对金额取整来改变比例；按规范允许必要的浮点转换。
4. 时间限制在实际物理表的最内层，与请求月末一致；不在外层重新选择或扩大统计时点。
5. 最内层 WHERE 对编号分组列的限制只能来自该表 Scope 的实际行策略，或编号恰为快照列时的指定时间。
   非权限的占比编号取值限制提前进入底层，报 RATIO_DENOMINATOR_FILTERED。
6. 对实际表声明的 Scope 行策略须保留在分组前的 AND 条件中，包括空策略的恒假条件；
   以本规则独立构造和识别 eq/in/恒假条件，不调用 compiler.conditions。缺失报 RATIO_SCOPE_POLICY_MISSING。

其他不符合占比规范形状的情况报 RATIO_SHAPE_INVALID；上述机器码均归 R-RATIO-001，严重度为 error。
继续运行既有只读、名字、范围及业务规则。不能为了通过占比而全局放宽多时点子查询等现有规则。

**校验责任边界**：L4 可以检查规范结构、时间和显式行策略，不凭 SQL 名字推断业务维度及指标本身是否选对。
SemanticCatalog 的代码映射、正确公式和“非拆分业务上下文没有丢失”仍由 L3、独立黄金 SQL 及 SQLite 业务结果测试共同守住。
不把派生列存在性校验的既有限制或无权限的数据现实证明，宣传成已经解决。

## 11. 黄金集和验收矩阵

从 G-019 起新增手写标准 SQL，至少包括：

- 普通产品贷款余额占比，包含金额、整体和小数比例。
- 机构上下文保留，单产品展示过滤在最外层，整体不被缩小。
- 占比维度的行权限位于底层，业务过滤仍在外层；整体只含可见产品。
- 空行权限恒假，不能把无权数据加入整体，也不能伪造结果行。

登记 covers/why_hard，覆盖 R-RATIO-001、R-PCT-001/C-07、R-NAME-001/C-11 等实际边界。
不改 G-001~G-018，不把新占比用例硬绑定到已有的不良率或增长率评测问题。

### 独立 SQLite 小样本

固定同一月末：B001 的 LP01=100、LP03=300、LP07=600，B002 的 LP03=900，使用整数金额。

- 按产品统计且机构上下文为 B001：整体 1000；LP03=300，占比 0.3。
- 只展示 LP03：仍为 300/1000，不变成 300/300。
- B001 上下文下，权限只允许 LP01/LP03：整体 400；LP03 占比 0.75。
- 业务机构条件和机构权限不相交、展示对象不存在或空策略：零行。

额外测试条件 SUM、NULL/零值/正负抵消、全 NULL、空源表、未知码值、重复名称与稳定编号、同义词去重、
额外来源拒绝、非法组合、输出冲突、自定义快照列和调用者别名、显式空表列权限、政策不被展示过滤替代。
