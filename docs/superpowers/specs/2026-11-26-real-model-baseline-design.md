# M5.1：真实模型基线评测

日期：2026-11-26。状态：**草案，待人工确认**。确认之后才出 Plan 和代码。

## 背景

到 M4 为止，项目的全部结论都来自 replay：模型响应是手写的，离线 71/71 只证明契约和确定性，
不证明真实模型能理解问题。L1 在真实模型下的字段准确率、端到端出数正确率、失败落在哪个阶段，目前都是未知。

现有工具不够用：

- `scripts.evaluate` 只跑 replay，报告顶层写死 `real_model=false`。
- `scripts.record_cassette.py` 会调真实模型，但它是录制工具，结果写进测试 cassette 目录，不评分、不留档、不控预算。
- `Settings.from_env()` 只读系统环境变量，项目里没有加载 `.env` 的代码；`.env.example` 只是变量清单。

## 目标

用一条命令对固定题集做真实调用，产出可复核的报告，回答三个问题：

1. 规范问法下，L1 的 Intent 字段准确率是多少。
2. 从问题到出数，端到端正确率是多少。
3. 失败落在哪个阶段，哪些题的结果不稳定。

## 非目标

- 不调 prompt、不改语义层、不改编译器和校验器。基线是测量，不是优化。
- 不新增题目，不修改任何题目的预期。
- 不做多轮澄清评测；单轮里出现追问只记录为结果，不替用户补答。
- 不评测思考模式，也不比较开与关的差异。
- 不实现 `.env` 自动加载。
- 不并发、不重试、不续跑；中断后重跑就是新的一轮。
- 不把真实调用的响应写进 `tests/cassettes`。
- 不换算费用。价格会变，报告只记 token 数。

| 改题禁令 | 看过结果后不得改题、改预期 | 要改就另起一轮并在报告里声明 |

### 客户端改动：关闭思考模式

DeepSeek 默认开启思考模式，且在思考模式下忽略 temperature。基线要求 temperature 0 真实生效，
所以客户端要能显式关闭它。现有 `OpenAICompatLLM` 还兼容其他厂商的接口，有的会拒绝不认识的字段，
因此做成可选参数，不设就不传：

- 新增环境变量 `WENSHU_LLM_THINKING`，取值为空、`enabled` 或 `disabled`；为空时请求体与现在完全一致。
- `OpenAICompatLLM` 增加对应的构造参数，设置时在请求体里加 `thinking` 对象；`Settings` 和工厂负责接线。
- `.env.example` 的模型名从 `deepseek-chat` 改为 `deepseek-flash`，并补上这个变量。
- 运行器把它作为前置条件：不是 `disabled` 就退出，保证基线的口径唯一。

这是模型调用边界上的改动，所以写进本 Spec；它只增加一个请求字段，不改变重试、解析和错误归一化。

## 题集与执行路径

| 套件 | 来源 | 题数 | 执行路径 | 判定依据 |
---|---|---|---|---|
| `extraction` | `tests/fixtures/intent_extraction/cases.yaml` | 20 | `extract_intent`，再按用例要求编译、校验 | 手写 `expected`、`expected_error`、`compile_error` |
| `execution` | `eval/cases/asset_quality.yaml` | 10 | `QueryService.start`：抽取、可答性、编译、L4、SQLite | `expected.result` 或 `expected.behavior` |

`extraction` 与离线评测的同名套件走完全相同的路径，这样两边的数字可以直接对比。
`execution` 每题只调用一次；返回追问或停止就记为该次的结果，不补答。

## 判定规则

**抽取套件**：把 `scripts.evaluate` 里现有的判定逻辑抽成共享模块，两边共用，不复制第二份。
规则不变：Intent 去掉 `raw` 后与手写预期相等；预期错误时错误码和 `fragments` 都要一致；
`compile_error` 时编译必须以该错误码失败；`compile: true` 时 SQL 必须通过 L4。

**执行套件**：按 `QueryService.start` 的返回类型定结果，再对照用例预期。

- 预期是数字：标量（AQ-001 到 004）要求首行至少一个数值单元格在 1e-6 内等于预期；
  按行键映射（AQ-005、006）要求每个键对应一行且数值相等、行数相等；
  按列名映射（AQ-007）要求首行各列数值相等；多行（AQ-008）要求逐行匹配且行数相等。
- AQ-009（数据缺失）：返回追问、停止或带披露的作答都算通过；静默给出一个数字算失败，归 `data`。
- AQ-010（不可答）：没有返回 `QueryAnswer` 且没有执行 SQL 就算通过。拒答文案里是否给出替代建议
  单独记为参考项，不计分，因为文案由引擎生成，不是模型的责任。
- 有黄金对照的 8 条 AQ，另记一个子指标：真实 Intent 编译出的 SQL 与对应黄金 SQL 是否结构等价。

**计分**：每次尝试记 `ok`。每题再算三个量：3 次全对、至少 2 次对、结果不稳定（对 1 或 2 次）。
套件层面同时报全对率和多数通过率，两个数差得远就说明模型输出不稳定，这本身就是结论。

**调用失败单独算**：超时、网络错误、非 2xx 响应归新阶段 `transport`，不计入理解失败，
也不进准确率的分母；受影响的题标记为未完成，在报告里单列。

## 执行流程

1. 前置检查：模式必须是 `real`；密钥、`base_url`、模型名非空；思考模式已关闭；输出目录不存在。
   任何一项不满足就退出，不发起调用。
2. 用记录型客户端包住真实客户端。它不重试、不改请求，只把每次调用的消息摘要、原文、返回的模型版本、
   `finish_reason`、token 数、耗时、异常记下来，并累计调用次数。
3. 逐题逐次执行：先跑 20 条抽取，再跑 10 条执行。每次调用前检查预算，连续 5 次 `transport` 失败就中止。
4. 汇总成报告并落盘。存在未完成或中止时，已拿到的结果照常保留。

## 输出

一次运行一个目录，包含四个文件：

| 文件 | 内容 |
---|---|
| `report.json` | 运行元数据、预算、两套指标、逐条结果 |
| `report.md` | 给人看的摘要：指标、失败表、不稳定题、固定的结论边界声明 |
| `calls.jsonl` | 每次模型调用一行：原文、版本、token、耗时、异常 |
| `review.md` | 人工归因模板，每条失败填阶段、原因和下一步动作 |

运行元数据至少包含：run_id、起止时间、git commit、请求的模型名、实际返回的版本号集合、接口域名、
prompt 协议版本（`PROTOCOL_VERSION`）、目录版本、采样参数、思考模式设置、重复次数、两份题集文件的 SHA256、
总调用数和总 token 数。
不包含密钥，也不包含本机绝对路径。

一律写到 `eval/real/<run_id>/`，这个目录加入 `.gitignore`，任何一次运行的输出都不提交。
跨电脑能看到的只有写进 `CONTEXT.md` 的数字和逐条归因结论，所以 `CONTEXT.md` 必须记下 run_id，
以及原始输出留在哪台电脑上。放在 `eval/` 而不是 `build/`，是为了不和可以随时删的构建产物混在一起。

`report.md` 末尾固定写明：题集只有 30 题且都是规范问法；只测了一个模型的一个版本；
temperature 为 0 也不保证逐字可复现；结论不代表真实用户问法的表现，也不代表可以上生产。

## 预算与安全

- `--max-calls` 默认 200。30 题各 3 次是 90 次调用，留一倍余量。用完即中止。
- 任何情况下都不回落到 replay 或 fake。
- 密钥只从环境变量读，不进命令行参数，不进输出文件。单测断言报告和 `calls.jsonl` 里不含密钥。
- 运行前在终端里设置变量，密钥用 `Read-Host` 输入，这样它不会留在 PowerShell 命令历史里：

```powershell
$env:WENSHU_LLM_MODE = 'real'
$env:WENSHU_LLM_API_KEY = Read-Host 'DeepSeek API Key'
$env:WENSHU_LLM_THINKING = 'disabled'
uv run python -m scripts.evaluate_real
```

## 失败方式

| 情况 | 行为 | 退出码 |
---|---|---|
| 模式不是 `real`、密钥为空、思考模式未关闭、输出目录已存在 | 不发起调用，直接退出 | 2 |
| 单次 `transport` 失败 | 记录该次，继续下一题 | 继续运行 |
| 连续 5 次 `transport` 失败，或调用数用完 | 中止，保留已有结果 | 3 |
| 模型输出不合协议 | 按 `ExtractionError` 的错误码记为 `understanding` 失败 | 继续运行 |
| 编译、校验、执行出错 | 记对应阶段和错误码 | 继续运行 |
| 运行器自身异常 | 记为 `runner` 阶段，不中断整轮 | 继续运行 |
| 跑完但有失败或未完成 | 正常落盘 | 1 |
| 全部完成 | 正常落盘 | 0 |

## 测试策略

全部测试都不调用真实模型，CI 保持零网络。

- 判定器：用手工构造的 Intent 直接调判定函数，覆盖三种结果形状、两条行为题、错误码不符、预期失败却成功。
  其中至少一条用正确 Intent 走完编译和 SQLite，证明判定器不会把对的判成错的。
- 记录型客户端：包一个按脚本返回的假客户端，断言调用次数、原文、token、异常都被记下，请求没有被改动。
- 客户端的思考模式参数：用 `httpx.MockTransport` 截获请求体，断言设置为 `disabled` 时带上该字段、
  不设置时请求体与改动前逐字段一致；非法取值在加载配置时报错。
- 预算与中止：调用数触顶、连续失败触顶时停止，之后的题不再调用。
- 前置检查：模式为 `replay` 或 `fake`、密钥为空、思考模式未关闭、目录已存在时退出码为 2，且假客户端一次都没被调用。
- 脱敏：密钥不出现在任何输出文件里。
- 汇总：全对率、多数通过率、不稳定题数的计算有独立用例，`transport` 失败不进分母。
- 回归：抽出共享判定后，`scripts.evaluate` 仍然是 71/71，报告内容除时间外不变。

## 实施顺序

给 Plan 的输入，T5 到 T7 是人工步骤，需要密钥，不进 CI。

1. T0：客户端的思考模式参数、配置接线和 `.env.example`，含请求体单测。
2. T1：把 `scripts.evaluate` 的判定逻辑抽成共享模块，补判定器单测，确认离线结果不变。
3. T2：记录型客户端、预算、中止逻辑及单测。
4. T3：运行器和报告，含前置检查、脱敏、汇总的单测。
5. T4：文档同步，提交一个不调真实模型的完整切片。
6. T5：冒烟。只跑 EX-001 一次，核对接口连通、耗时、`finish_reason` 和 token 数。
7. T6：全量运行 30 题各 3 次，保存为基线。
8. T7：人工逐条归因失败样本，把数字和结论写进 `CONTEXT.md`。

T5 是一道闸：如果冒烟显示输出被截断、耗时不可接受或连续调用失败，就停下来先查原因，不直接进 T6。

## 验收标准

- 模式不是 `real`、密钥为空或目录已存在时，命令不发起任何调用。
- 请求体带关闭思考模式的字段；未设置该参数时，请求体与改动前一致。
- 所有不过真实模型的测试通过；`scripts.evaluate` 仍为 71/71；Ruff 通过。
- 冒烟记录齐全，并写明是否进入全量运行。
- 全量运行在预算内结束，`report.json`、`report.md`、`calls.jsonl` 齐全，每条失败都有阶段、错误码和模型原文。
- 没有任何文件写进 `tests/cassettes`，输出里不含密钥。
- 运行目录被 Git 忽略，`git status` 里看不到任何运行输出。
- 运行期间 prompt、语义层、编译器没有改动，报告里的 commit 与代码一致。
- `CONTEXT.md` 的结论措辞符合 `EVALUATION.md` 第 9 节，不把基线数字说成真实用户问法的准确率。
