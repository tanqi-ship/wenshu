# 术语表

本文件统一项目中的核心术语。新会话、文档、代码注释和评测报告应使用相同含义。

## 架构与执行

| 术语 | 含义 |
|---|---|
| L0～L5 | 项目的六层流水线：输入边界、理解、门禁、编译、校验、执行。 |
| Intent | 模型对用户问题的结构化表达，包含指标、时间、维度、过滤、对比等，不含 SQL 语法。 |
| Scope | 本次提问的权限输入，包含可见表、列和行级策略；不是用户/角色系统。 |
| RowPolicy | `Scope` 中的行级策略，例如只能看 `org_no = 'B001'`。 |
| 编译器 | 读取 `Intent + SemanticCatalog + Scope`，确定性地生成 sqlglot AST 和 SQL。 |
| 校验器 | 独立解析 SQL 文本，检查只读、名字、范围和业务规则；不读取编译器中间产物。 |
| 执行器 | 在只读、超时、行数上限等约束下执行已验证 SQL，当前实现为 SQLite。 |
| fail-closed | 出错或权限不明时默认拒绝，而不是放行或跳过。 |
| `slots_complete` | 必需槽位不缺，但不等于可答、可编译、有权限或有数据。 |
| `needs_clarification` | 当前问题缺少必需槽位，需要追问。 |
| `UNANSWERABLE` | 语义层没有该指标或概念，当前系统不能回答。 |
| `OUT_OF_SCOPE` | 指标存在，但当前 Scope 没有权限完成查询。 |

## 语义层

| 术语 | 含义 |
|---|---|
| 语义层 | 业务概念到物理表列、公式、码值和关系的登记表。 |
| `SemanticCatalog` | 编译器读取的不可变语义层容器。 |
| `MetricDef` | 指标定义：编码、名称、公式、单位、来源表、同义词。 |
| `DimensionDef` | 业务维度定义：编码、名称、同义词、口径/粒度。 |
| `LevelDef` | 某个维度口径对应的物理分组列、展示列和来源表。 |
| `RelationDef` | 表之间的关系、关联列、JOIN 类型和基数声明。 |
| `ReportDef` | 预计算报表来源：指标、值列、月份列、固定维度和月份分表。 |
| `code_map` | 业务显示值到数据库存储值的映射，例如“渝北支行”到 `B001`。 |
| `bank_mini.py` | 当前演示和测试共用的硬编码语义层，不是生产配置。 |
| 物理表结构目录 | 校验器使用的表、列、schema 名字目录；与业务语义层分开。 |
| 可配置语义层 | 从外部配置加载 `SemanticCatalog` 的能力；当前尚未实现，配置格式（YAML / JSON / Apache Ossie 等）由对应 Spec 确定后再登记。 |

## 模型与回放

| 术语 | 含义 |
|---|---|
| LLM | 大语言模型。当前只在 L1 理解层允许调用。 |
| `fake` | 测试用模型实现，按脚本返回固定结果。 |
| `replay` | 回放固定 cassette 的模型实现，CI 和离线评测使用，不联网。 |
| `real` | 真实模型实现，本地手动验证使用。 |
| 思考模式 | 模型先产生推理再作答的模式；真实基线要求关闭，否则接口会忽略 temperature。 |
| 记录型客户端 | 包住任意 `LLMClient`，记录调用、token、耗时和异常，并执行调用预算的包装器。 |
| cassette | 保存模型请求和响应的固定回放文件。 |
| `ReplayMiss` | replay 模式找不到对应记录时抛出的错误；不得回退到真实模型。 |
| prompt | 发送给模型的指令和上下文。Prompt 变更视为代码变更，必须评测。 |
| 模型调用次数 | 一个问题的理解、补答或重试过程中实际调用模型的次数。 |

## 测试与评测

| 术语 | 含义 |
|---|---|
| 测试 | 验证特定函数、模块或契约在特定输入下是否按预期工作。 |
| 评测 | 在代表性问题集上衡量系统整体表现。 |
| 黄金集 | 人工编写的标准 SQL，用于判断编译器产物是否结构等价。 |
| 基线 | 固定模型、版本、题集与采样参数下的一次完整真实调用运行。 |
| 全对率 | 每题重复 N 次全部成功的题数占完成题的比例。 |
| 多数通过率 | 每题至少 ⌊N/2⌋+1 次成功的题数占完成题的比例。 |
| 不稳定题 | 重复中既有成功又有失败的题；提示模型输出不稳定。 |
| `transport` | 超时、网络错误或非 2xx 响应；单独归因，不计入准确率分母。 |
| 排除题 | 因语义层缺口或题面/prompt 冲突当前无法公平测量的用例；以 `measurement.status=excluded` 标记，单列且不进准确率分母。 |
| 评测集 | 用于衡量整体准确率的问题集合，包含 `why_hard` 和 `covers`。 |
| 结构等价 | 忽略排版、大小写等差异后，SQL AST 结构一致。 |
| 结果准确率 | 实际执行返回的数据与人工结果集一致的比例。 |
| 失败归因 | 将失败样本划分到 understanding、clarification、semantic、scope、compiler、validation、execution、data、transport 等阶段。 |
| 自动 bless | 用引擎产出覆盖黄金答案；本项目禁止。 |
| 覆盖率 | 评测集被黄金集或测试覆盖的程度，不等于准确率。 |

## 本体与路由（规划中）

| 术语 | 含义 |
|---|---|
| 本体 | 对业务概念、属性、关系、计算定义和来源的共享、可治理描述。 |
| Term | auto-ontology 中的业务概念，例如客户、发票行。当前 wenshu 未接入。 |
| ColumnAttribute | 概念到物理列的映射。当前 wenshu 未接入。 |
| SqlAttribute | 概念下的受控 SQL 计算定义。当前 wenshu 未接入。 |
| semantic FK | 经过数据确认的语义外键关系。当前 wenshu 未接入。 |
| 本体快照 | 某次编译或问答使用的不可变本体版本；未来与 `SemanticCatalog` 对齐。 |
| 路由 | 根据问题能力、语义覆盖和权限选择确定性编译、澄清、拒答或 ReAct。 |
| ReAct | 模型通过工具循环检索、执行草稿并提交答案的代理模式；当前 wenshu 未实现。 |
| 双路由 | 确定性编译器与本体驱动 ReAct 并存的架构设想；尚未实现。 |
| 路由准确率 | 系统是否为问题选择了预期执行路径的比例。 |

## 工程流程

| 术语 | 含义 |
|---|---|
| Spec | 单个功能的设计规格，定义目标、非目标、接口、失败方式和测试策略。 |
| Plan | 可执行任务清单，包含改动和验证方式。 |
| ADR | Architecture Decision Record，记录架构决策、理由和翻案条件。 |
| Definition of Done | 任务完成必须满足的全部条件。 |
| WIP 分支 | 未完成但已推送的工作分支，用于跨机器继续任务。 |
| 双机协议 | 家里电脑和工作笔记本之间通过 commit/push/pull 同步的流程。 |
| `CONTEXT.md` | 当前项目状态、下一步和已知问题的唯一事实来源。 |
